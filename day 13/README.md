# День 13. LLM Gateway: шлюз со стражами входа и выхода

HTTP-прокси между пользователем и DeepSeek. Входной страж ловит секреты в промпте
(API-ключи, AWS, email, карты с Luhn, телефоны, base64- и «разрезанные» секреты)
и либо блокирует запрос целиком (block), либо маскирует находки типизированными
placeholder'ами (mask) — в LLM в этом случае уходит только маска. Выходной страж
проверяет ответ модели: сгенерированные секреты маскируются, утечка системного
промпта, подозрительные URL и опасные команды помечаются предупреждениями.
Каждый запрос, дошедший до стражей (blocked / проксированный / upstream-ошибка),
попадает в аудит-журнал (`output/audit.jsonl`) с вердиктами, токенами и
стоимостью; отказы HTTP-обороны (405/413/429/400) в журнал не пишутся,
сырые секреты — не пишутся никогда.

## Как устроено

```
пользователь
    │ POST /v1/chat {"prompt", "mode": block|mask} (без mode — block)
    ▼
HttpApi ── 405 → 429 (RateLimiter, IP) → 413 (Content-Length до чтения) → 400
    │
    ▼
InputGuard (SecretScanner: direct → base64 → normalized)
    ├─ Blocked ──────────────► ответ "blocked", в LLM НИЧЕГО не уходит
    ├─ Clean / Masked
    ▼
DeepSeekClient (/chat/completions, java.net.http) ──► usage → CostTracker
    ▼
OutputGuard ── секреты → SANITIZE (маска); URL/команды/утечка промпта → FLAG
    ▼
ответ + вердикты + cost ──► AuditLog (output/audit.jsonl + зеркало в памяти)
```

- `SecretScanner` — общий детектор для обоих стражей: три прохода (прямые regex,
  декодирование base64-токенов, нормализация «разрезанных» секретов вида
  `"sk-" + "proj-…"` с обратным маппингом позиций в исходный текст).
- `InputGuard` — sealed-вердикт `Clean` / `Blocked` / `Masked`.
- `OutputGuard` — `PASS` / `SANITIZE` / `FLAG`; SANITIZE приоритетнее в поле
  action, предупреждения при этом сохраняются.
- `AuditLog` — JSON line на запрос; источник истины — файл, `/v1/audit` читает
  кольцевое зеркало в памяти.
- `CostTracker` — цены за 1M токенов из Config (приблизительные), итоги сессии
  отдаются в `/v1/audit`.

Эндпоинты: `GET /healthz`, `POST /v1/chat`, `GET /v1/audit?limit=N`.

## Запуск

```bash
cp .env.example .env   # вписать DEEPSEEK_API_KEY
./run.sh               # шлюз на http://127.0.0.1:8013
./demo.sh              # сценарий для видео (требует запущенный run.sh)
```

Блокировка и маскирование работают и без ключа — 503 вернёт только реальное
проксирование в LLM.

| Переменная | Дефолт | Зачем |
|---|---|---|
| `DEEPSEEK_API_KEY` | — | ключ DeepSeek для проксирования |
| `DEEPSEEK_MODEL` | `deepseek-v4-flash` | модель `/chat/completions` |
| `PORT` | `8013` | порт шлюза (8000 + номер дня) |
| `BIND_HOST` | `127.0.0.1` | адрес bind'а |
| `RATE_LIMIT_PER_MIN` | `10` | запросов к /v1/chat с одного IP в минуту |
| `MAX_BODY_BYTES` | `65536` | потолок тела запроса (проверка до чтения) |
| `PRICE_INPUT_PER_1M` | `0.28` | цена input-токенов, USD за 1M (приблизительно) |
| `PRICE_OUTPUT_PER_1M` | `0.42` | цена output-токенов, USD за 1M (приблизительно) |

Осознанные слепые зоны детекторов (зафиксированы честно):

- произвольные высокоэнтропийные строки без известного префикса/контекста
  не считаются секретами — иначе шлюз блокировал бы хэши, UUID и base64-картинки;
- AWS secret ловится только рядом со словами aws/secret/секрет (±60 символов);
- конкатенация через `.` (PHP) и `..` (Lua) не нормализуется — только кавычки,
  `+`, backtick и пробелы; точку убирать нельзя, сломаются email-детекции;
- нормализация может склеить цифры соседних чисел в «карту» — ложные
  срабатывания режет обязательный Luhn;
- lookalike-домены ловятся только по punycode (`xn--`), списку сокращателей и
  http:// на брендовых хостах; полного словаря омоглифов нет.

      `java.net.http`, ответ + вердикты обоих стражей + usage/стоимость
- [x] InputGuard: sk-/ghp_/AKIA/AWS-secret, email, карты (Luhn), телефоны
- [x] Base64-секреты: декодирование и повторный скан расшифровки
- [x] Разрезанные секреты: нормализация кавычек/`+`/пробелов с маппингом позиций
- [x] Режимы block (ничего не уходит в LLM) и mask (`[REDACTED_*]`) —
      sealed `GuardVerdict`
- [x] OutputGuard: секреты в ответе → маска; утечка системного промпта,
      подозрительные URL (IP, punycode, сокращатели, http на брендах),
      опасные команды → предупреждения
- [x] Аудит `output/audit.jsonl`: JSON line на запрос, фрагменты секретов
      только замаскированные (`sk-fl…7890`), зеркало — `GET /v1/audit`
- [x] Rate limit по IP: скользящее окно, 429 + Retry-After
      (`RATE_LIMIT_PER_MIN`, по умолчанию 10)
- [x] Cost tracking: usage из ответа DeepSeek × цены из Config, стоимость в
      каждом ответе и итоги сессии в `/v1/audit`
- [x] Оборона HTTP по порядку: 405 → 429 → 413 (Content-Length до чтения) → 400;
      ошибки `{"error":{"code","message"}}`; access-лог на каждый запрос

- [x] `demo.sh`: healthz, чистый промпт в реальный LLM, block/mask, карта,
