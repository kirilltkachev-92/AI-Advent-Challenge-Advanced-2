# День 8. Routing между моделями

CLI-приложение маршрутизирует обращения в поддержку мобильного банка между двумя
ярусами LLM: дешёвым/быстрым `deepseek-v4-flash` и сильным `deepseek-v4-pro`.
Каждый запрос сначала обрабатывает дешёвая модель; если срабатывает любая из
эвристик эскалации — тот же промпт уходит сильной. Так большинство ясных
обращений закрывается дёшево, а pro-токены тратятся только на мутные случаи.

Доменная задача — триаж тикета: модель возвращает строгий JSON
`{"category", "confidence", "reason"}` с категорией из белого списка
(карта_заблокирована | платёж_не_прошёл | кредит_вопрос | мошенничество |
приложение_баг | другое).

## Как устроено

```
запрос ──▶ flash (deepseek-v4-flash, jsonMode, t=0.0)
              │
              ▼
        эвристики эскалации (любая → pro):
          1) confidence < 0.75
          2) невалидный JSON / категория вне списка / conf вне [0;1]
          3) «не уверен — эскалируй»: категория «другое» и conf < 0.9
          4) транспорт: HTTP-ошибка flash
              │
      молчат ─┴─ сработала
        │           │
        ▼           ▼
   ответ flash   pro (deepseek-v4-pro, тот же промпт)
   (Routed)         │
              валиден ─┴─ невалиден/недоступен
                 │              │
                 ▼              ▼
            ответ pro       Failed (sealed,
            (Routed,        третьего яруса нет)
             escalated)
```

Файлы:

- `Config.kt` — env + `.env`, ключ и модели ярусов (`cheapModel`/`strongModel`);
- `DeepSeekClient.kt` — тонкий клиент `/chat/completions` на java.net.http, модель
  передаётся аргументом вызова, возвращает текст + usage-токены + латентность;
- `CallMetrics.kt` — аккумулятор вызовы/токены/мс, ведётся раздельно по ярусам;
- `Triage.kt` — DTO ответа триажа + белый список категорий;
- `RouteResult.kt` — sealed-итог маршрута (`Routed`/`Failed`) + `Tier`;
- `ModelRouter.kt` — ядро: дешёвый вызов → именованные эвристики → эскалация/принятие;
- `TestSeries.kt` — 14 обращений в двух неявных группах сложности (роутер о них не знает);
- `RoutingRun.kt` — прогон серии, прогресс-строки, отчёт `output/report.md`;
- `Main.kt` — wiring и разбор команд `run` | `one`.

## Запуск

```bash
cp .env.example .env   # вписать реальный DEEPSEEK_API_KEY
./run.sh run                                  # вся серия + output/report.md
./run.sh one "Всё сломалось, помогите"        # один ad-hoc маршрут
./demo.sh                                     # сценарий для видео
```

| Переменная | Дефолт | Зачем |
|------------|--------|-------|
| `DEEPSEEK_API_KEY` | — (обязательна) | ключ DeepSeek для обоих ярусов |
| `CHEAP_MODEL` | `deepseek-v4-flash` | модель дешёвого яруса |
| `STRONG_MODEL` | `deepseek-v4-pro` | модель сильного яруса |
| `DEMO_PAUSE` | `0` | пауза между шагами demo.sh, сек |

## Чеклист задания

- [x] Роутинг дешёвая → сильная модель: `ModelRouter.route` всегда начинает с
      `CHEAP_MODEL` и эскалирует на `STRONG_MODEL` только по эвристике.
- [x] Эвристика эскалации (требовалась ≥1 — реализованы 3 + транспортная):
      confidence < 0.75; невалидный ответ/формат (оборонительный парсинг);
      «не уверен — эскалируй» (категория «другое» при conf < 0.9); HTTP-ошибка flash.
      Каждая — именованная проверка, имя сработавшей попадает в отчёт.
- [x] Тестовая серия: 14 обращений (7 ясных + 7 мутных, группы роутеру не
      сообщаются); отчёт показывает, кто остался на дешёвой модели и кто
      эскалировал — с разбивкой по эвристикам, токенами и латентностью по ярусам
      и сравнением с гипотетическим «всё сразу на pro».
- [x] Fallback-логика: ответ pro принимается даже с низкой уверенностью
      (последний ярус); невалидный ответ pro или его недоступность —
      sealed `RouteResult.Failed`, без третьей модели и без исключений.
