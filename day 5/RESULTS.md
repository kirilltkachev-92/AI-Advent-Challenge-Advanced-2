## Усиление между прогонами (почему run 2 быстрее)

Run 1 сам нашёл баг: API DeepSeek больше не принимает дефолт `deepseek-chat`
(агенты задач 2 и 4 тратили время на диагностику) → заведён issue #17.
Перед run 2: фикс #17 (`deepseek-v4-flash`, живая проверка API) + правило
в CLAUDE.md. Результат: −20% общего времени, максимальные дельты именно на
задачах с живыми прогонами (#4 −1:42, #10 −2:01).

## Облако vs локальная модель

- Локалка выдержала ровно **однофайловые** задачи (3 шт. за 2:16 — в 5 раз
  быстрее облака на задачу) и умерла на первом многофайловом рефакторинге:
  переписывая HttpApi.kt, потеряла типизацию kotlinx-JSON-билдера.
- Причина слома — класс «сгенерировал нерабочий код» (не «не понял контекст»,
  не «зациклился»).
- Рецепт: локалке — однофайловый хвост очереди, многофайловое и агентное — облаку.
